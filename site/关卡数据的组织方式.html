How to organise level data

这一步决定什么What this stage decides：关卡写死在代码里，每次改关卡都要 AI 重写一大段代码 —— 这是 AI 迭代最容易失控的地方。: Levels hardcoded in the code mean every level change asks AI to rewrite a big chunk of it — the easiest place for AI iteration to spiral out of control.

本站的判断Our judgement：把关卡放进数据（网格 tilemap 或简单数组），代码只负责读数据；碰撞用引擎的碰撞层，别让 AI 手写坐标判断。: Put levels in data (a tile grid or a plain array) and let the code only read it; use the engine's collision layer instead of asking AI to hand-write coordinate checks.

性质：部分可核验Nature: partly verifiable

一句话：AI 改代码会引入错误，改数据不会 —— 所以关卡应该是数据，不是代码。

（这是本站基于「数据与代码分离」工程常识的判断，下面给出主流引擎的官方做法作依据。）

In one line: AI editing code introduces bugs; AI editing data usually does not — so levels should be data, not code.

(This is this site's engineering judgement about separating data from code; the mainstream engines' official practice below is the evidence.)

主流做法：网格（tilemap）+ 图层

三大引擎的官方文档都把关卡描述成「网格上的数据」：

The mainstream approach: a tile grid plus layers

All three engines' official docs describe levels as data on a grid:

EngineOfficial wording (checked that day)Source

Phaserthe official Making your first Phaser 3 game tutorial builds its level from a tilemapphaser.io tutorial Part 5, 2026-10-29

为什么这对 AI 工作流特别重要

关卡在代码里时，「把第三段平台往左移」这种小改动意味着让 AI 重写一段渲染+碰撞代码 —— 每次重写都是一次出错机会。关卡在数据里时，同样的改动只是改几个数字或一格瓦片，AI 出错一眼能看出来。

  • 地形 → 网格数据（tilemap 文件，或代码里的二维数组）
  • 出生点、机关、可互动物 → 对象层或单独的配置数组
  • 碰撞 → 用引擎自带的碰撞层/碰撞组，不要让 AI 手写坐标区间

（这一节是本站对 AI 迭代方式的分析，不是引擎文档原话。）

Why this matters extra for AI workflows

When the level lives in code, "move the third platform left" means asking AI to rewrite a chunk of rendering plus collision code — every rewrite is a fresh chance to break something. When the level lives in data, the same change is a few numbers or one tile cell, and a mistake is obvious at a glance.

  • Terrain → grid data (a tilemap file, or a 2D array in code)
  • Spawns, traps, interactables → an object layer or a separate config array
  • Collision → the engine's built-in collision layer/groups; never let AI hand-write coordinate ranges

(This section is this site's analysis of AI iteration, not engine-doc wording.)

什么时候不用 Tiled 也够

极简原型（见 最小可玩原型）里，代码内一个二维数组就是关卡数据 —— 不需要编辑器、不需要 TMX 文件。等你需要可视化编辑、多关卡管理时再迁到 Tiled 这类工具，迁移成本很低（数据本来就在数据里）。

⚠ 反模式是把关卡「画」在代码里：每个平台一行 add.rectangle(x, y, w, h)。原型阶段偶尔可以，改三版之后它会变成最难维护的部分。

When you don't need Tiled

For a bare prototype (see minimal playable prototype), a 2D array in the code is level data — no editor, no TMX file. Move to a tool like Tiled when you want visual editing or multiple levels; the migration is cheap because the data was already data.

⚠ The anti-pattern is "drawing" the level in code: one add.rectangle(x, y, w, h) line per platform. Fine occasionally in a prototype; after three revisions it becomes the hardest part to maintain.
