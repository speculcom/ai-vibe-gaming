S1 · Pick an engine

这一步决定什么What this stage decides：按目标平台、玩法和已有经验，检查引擎是否满足项目约束。: Check an engine against target platforms, gameplay and existing experience.

本站的判断Our judgement：先确定最小玩法与发布目标，再查看对应版本的文档和导出限制。: Define minimal gameplay and the release target before checking versioned documentation and export limits.

性质：本站的判断，未经实测Nature: the site's judgement, not measured

先写四个条件

用一段话写清：2D 还是 3D、发到哪里、最小玩法是什么、你熟悉哪种语言或工具。已有工程和资产也算条件。

不必因为项目只有一个人，就直接排除某个引擎；也不要因为未来可能需要 3D，就现在承担没有必要的工作。

Write four conditions first

State 2D/3D, release platform, minimum gameplay and familiar languages/tools. Existing projects and assets matter too. Team size alone does not exclude an engine; a possible future need for 3D does not automatically justify extra work now.

先看档案，再做小验证

Godot、Unity、Unreal、Bevy、libGDX 的语言、资源流程和导出方式各有不同。按项目要求逐项核对，不用“原生引擎”一个标签判断 Web 支持。

Phaser、Pixi 和 Three.js 的职责也不同。先查场景、渲染、物理、打包分别由谁负责，避免把渲染库当成已经包含全部游戏功能的工具。

Read the profile, then validate a small slice

Godot, Unity, Unreal, Bevy and libGDX have different languages, asset pipelines and export options. Check each requirement rather than inferring Web support from the “native engine” label.

Phaser, Pixi and Three.js also have different responsibilities. Establish who supplies scenes, rendering, physics and packaging; a rendering library is not automatically a complete game toolchain.

一个选型记录示例

以下是假设项目，不是实测推荐：做一个 2D 网页接方块小游戏，已有 JavaScript 经验，希望用键盘和触屏操作。

先比较能覆盖这些约束的候选，检查官方文档对应的版本。用一个场景验证输入、碰撞、计分、重新开始和浏览器导出。记录没通过的条件，再决定保留哪个候选；不用星数或“AI 更擅长哪种语言”代替这个过程。

Example selection record

Hypothetical project, not a measured recommendation: a 2D browser block-catching game, with JavaScript experience and keyboard/touch input.

Compare candidates against those constraints and their versioned docs. Check input, collision, scoring, restart and browser export in one scene. Record failed conditions before selecting; stars or assumed AI language skill are not substitutes.

这一步完成后

留下一份选择记录：候选、目标版本、已满足的条件、仍未知的限制和选择原因。接着进入 核心循环。如果导出平台仍不确定，先看 Web 导出可行性。

档案中的来源与核验日是公开资料快照，不是本站已经运行过各引擎的证明。

When this step is done

Keep a record of candidates, target version, satisfied conditions, unknown limits and reasons for the choice. Continue to the core loop. If the platform is unresolved, read Web export feasibility.

Profile sources and dates describe public-document snapshots, not execution tests by this site.
