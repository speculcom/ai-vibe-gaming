使用条件与检查

⚠ 下面讨论语言与工具链条件；本站没有测量生成代码的错误率。

原因说明
GDScript 语法部分语法与 Python 相似，但 API、类型与场景访问应按目标 Godot 版本核对
错误信息友好脚本报错会指出行号与变量名，AI 能据此定位
官方文档完整类参考有明确的参数与返回值，AI 引用的 API 大多真实存在
静态类型可选GDScript 支持类型标注，AI 可以写出更安全的代码
⚠ 不用 C#选 C# 就要 .NET 环境，AI 常写出版本不匹配的 API

Usage conditions and checks

⚠ What follows is our judgement of how likely AI is to get it wrong, not a measurement.

ReasonExplanation
GDScript syntaxSome syntax resembles Python; verify APIs, types and scene access against the target Godot version
Friendly error messagesScript errors point at a line and a variable name, which is enough for AI to locate the problem
Complete official docsThe class reference documents parameters and return types; most APIs AI cites actually exist
Optional static typingGDScript supports type annotations, so AI can produce safer code
Choosing C# pulls in a .NET environment, and AI frequently writes APIs from the wrong version

它的代价

  • Web 导出不算完整：存档、性能、加载在大项目上会出问题
  • C# 支持仍在推进：⚠ 官方文档自己列了一长串「已知问题」，别当稳定特性用
  • 生态比 Unity 小：找现成插件的余地少

What it costs

  • The web export is not complete — saves, performance and loading fall apart on larger projects
  • C# support is still being worked on — ⚠ the official docs list a long set of known issues; do not treat it as stable
  • A smaller ecosystem than Unity — fewer ready-made plugins

GDScript 与项目生态的使用条件

使用 Godot 场景树时，要把节点结构与脚本路径说明清楚：

  • 场景是 .tscn 文本格式，
  • AI 写 .tscn 文件经常格式错误

⚠ 正确做法：让 AI 写 GDScript 代码，场景在编辑器里搭。

这与 S2「给明确的边界」是同一条原则。

GDScript is steadier for AI, but the ecosystem has limits

Provide scene structure and node paths when generating scripts:

  • Scenes are .tscn text files — but they are generated by the editor and should not be hand-written
  • AI-written .tscn files are frequently malformed

⚠ : let AI write GDScript, and build the scene in the editor.

That is the same rule as S2's "give explicit boundaries".

什么时候不该选

  • 你要做大型商业项目（生态与人才储备都不够）
  • 你要完全体的 Web 游戏（导出受限）
  • 你不写代码（那该用更简单的方案）

When not to pick it

  • You are building a large commercial project (the ecosystem and talent pool are both thin)
  • You need a (the export is limited)
  • You (there are simpler options)

最小 starter

一个能移动的 CharacterBody2D，用 Input.get_vector 读方向。片段只做最小验证。

extends CharacterBody2D
var speed := 300.0

func _physics_process(delta):
    var dir := Input.get_vector("left", "right", "up", "down")
    velocity = dir * speed
    move_and_slide()

官方文档：https://docs.godotengine.org/
